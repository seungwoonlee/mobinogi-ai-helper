## 2. 검증

- 전체 테스트 144건 통과(모의 CLI 기반, `python -m unittest discover -s tests -t .`).
- 실제 게임 CLI 호출 0건: 테스트 가드 위반 카운터가 모든 테스트에서 0이다. 가드는 `Popen`·`os.system`·`os.spawn*`·
  `_winapi.CreateProcess`를 감싸며 위반을 `BaseException` 계열로 던진다.
- 03 §10 결함 9개 해결(계획 §6 표): 판정표, 종료 코드 비단정, 제한 시간·트리 정리·중단 처리, 배열 응답 분류, 단계별 결과,
  알 수 없는 status 불명 처리, 값 객체 판정과 정규화, 행동 규칙 예외, 오류 출력에서 원문 제거.
- 원문 미기록: 카나리(모의 CLI가 argv·stdout·stderr로 에코)를 표준 출력·로그·저장 파일·예외 표현에서 검사(Base64
  표준·URL-safe·패딩 유무, JSON 이스케이프, UTF-16·cp949 바이트, 퍼센트 인코딩, 부분 조각).
- 채팅 경로 퍼징 200회(시드 고정): 성공으로 추측한 경우 0건, 행동 오실행 0건, 채팅 호출 1회.

## 2.1 리뷰 1회차에서 고친 것

- 구현 리뷰(높음 1·중간 6): Windows에서 죽은 소유 프로세스를 DEAD로 판정, 손자 프로세스가 파이프를 쥔 채 정상 종료할 때의
  멈춤(`read1`, 닫지 않고 스레드 폐기), 최상위 `null`이 body의 error·retryAfter를 가리는 문제, 불명 채팅의 결과 기록(`UNRESOLVED`)을
  결과 저장과 함께 남기기, 행동 재전송 중 크래시 시 재전송 재허용 차단, 브로커의 `FAILED` 전이·관찰자 오류 격리·예외 시 상태
  복귀, 오래된 세대의 실패 응답 폐기.
- 테스트 리뷰(높음 3·중간 6): 패키지 로드 시 CLI 환경 변수를 모의 CLI로 고정, `_winapi.CreateProcess` 가드가 명령줄을 인자로 풀어
  같은 허용 규칙을 적용(직접 호출 거부 시험 포함), 실제 전송 문자열(카나리+이모지)의 변형까지 유출 검사, 채팅 경로 오류 주입 확대
  (종료 코드 2~5, 빈 응답, 잘못된 UTF-8·cp949, 출력 상한 이상·이하), Ctrl+C, 손자 프로세스 정리 확인, 고정 sleep을 호출 로그 대기로 교체,
  추적표 단언 검사 강화.

## 2.2 리뷰 2회차에서 고친 것

- 구현 리뷰(높음 2·중간 2): `retryAfterSeconds: 0`이 파이썬의 `0 == False` 때문에 "마커 없음"으로 오판정돼 전송이
  확정(`SENT`)되던 결함(`response_validator.find_marker`를 `is`/`==` 값 종류별 비교로 수정), 깊게 중첩된 JSON이
  `RecursionError`를 던져 `KeyError`로 전송 경로 전체가 죽던 결함(`parse_json`이 `RecursionError`도 `JSON_ERROR`로
  분류하도록 수정). 브로커의 `FAILED` 전이가 C16(미전송 확정)·C17(결과 불명)을 구분하지 않는 점과 손자 프로세스가
  파이프를 쥐고 있을 때의 스레드·FD 누수는 각각 3단계·7단계 착수 전 재검토 과제로 남긴다(`reviews/05-구현-2단계-리뷰-2.md` M1·M2).
- 테스트 리뷰(높음 1·중간 1): 위 `retryAfterSeconds: 0` 회귀 테스트 추가(`test_retry_after_zero_is_still_a_marker`,
  `test_markers_block_success`, `test_review_fixes_2.py`), 실제 프로세스 기동 속도에 좌우되던 비결정적 테스트
  (`test_keyboard_interrupt_during_send_is_unresolved_and_skips_behaviour`)를 모의 CLI 호출 로그 관찰 기반으로
  교체, "출고 설정은 고정 픽스처로 테스트"라는 완료 조건을 어기고 저장소의 실제 `config/known_responses.json`을 읽던
  테스트를 고정 픽스처로 교체(표본 확보 뒤에도 깨지지 않음), 표준 출력 유출 검사의 부분 조각(6자) 위치 제약 누락을
  보완. `asyncio` 서브프로세스 함수 미보호(테스트 가드)와 `_winapi.CreateProcess` 계층이 Linux에서 검증 불가한 점은
  `reviews/05-구현-2단계-테스트리뷰-2.md` M2·M4에 남겨 다음 단계(7단계, Windows 실행)에서 처리한다.
- 퍼징 후보에 `retryAfterSeconds: 0`과 깊게 중첩된 `"["*5000`을 추가해(`tests/test_broker_chat.py`) 같은 부류
  결함을 향후 회귀로도 잡게 했다.
- 전체 테스트 144건 통과(모의 CLI 기반, 5회 반복 실행으로 flaky 재발 없음 확인).

## 3. 알려진 제한과 미검증 항목

- **성공·거부 응답 형식 미확인**: 출고 상태에서는 모든 채팅이 "확인 불가"(사유 `NO_KNOWN_RESPONSES`)이고 행동은 실행되지
  않는다. `tools/capture_sample.py`로 사용자가 승인해 표본을 확보한 뒤 설정을 채워야 한다(별도 작업, 아직 하지 않음).
- 코드 5의 `game_off`·`option_off` 구분, 캐릭터 미접속 응답 형식(C36은 판정 함수 주입으로 시험), 채팅 길이 계산 단위,
  허용 행동 목록 조회 명령은 `[가정]`이다(02 §18, 03 §12).
- **프로세스 간 경합**: 브로커의 직렬화와 60초 동일 문구 확인은 한 프로세스 안에서만 유효하다. 저장은 컨텍스트별
  파일이라 서로 덮어쓰지는 않는다. 인자 모드에서는 60초 확인이 성립하지 않으며 저장된 미확인 `UNRESOLVED`만 근거다.
  단일 실행 잠금(02 §6.3)은 7단계에서 구현한다.
- 공백·한글이 든 CLI 실행 파일 경로의 실제 실행은 가드가 허용하는 모의 CLI 경로가 하나뿐이라 자동 테스트로 시험하지 못했다(경로 탐색은 시험함).
- 소유 프로세스 판정은 Windows `GetProcessTimes`에 의존한다. 얻지 못하면 판정 불가로 두고 기록을 바꾸지 않는다.
- 행동 이름은 저장하지 않으므로 앱 재시작 뒤에는 `행동만 다시 보내기`를 할 수 없다.
- `input()`은 타이핑과 붙여넣기를 구분하지 못해 모든 전송을 확인을 거친 붙여넣기로 처리한다. 터미널에서 실행한 스크립트가
  tty를 상속하면 터미널 판정이 막지 못한다.
- Base64 인자는 같은 PC의 프로세스 목록에서 보일 수 있다(03 §8).
- `ACTION` 실행, 화해, 대기 슬롯, 초안, 게임 상태 감지는 이 단계 범위가 아니다.
- 브로커의 `FAILED` 전이가 02 §5.3의 C16(미전송 확정)·C17(결과 불명)을 구분하지 않는다(사용자 노출 `Outcome`은
  정확하다). 3단계(연결 감지) 착수 전에 해소하거나 02 §5.3과의 관계를 문서에 명시할 것.
- 손자 프로세스가 파이프를 계속 쥐고 있으면 스레드·파이프 FD가 그 프로세스 생애주기 내내 회수되지 않는다. 상시
  실행 앱(7단계) 착수 전 재검토 필요.
- 테스트 가드는 `subprocess.Popen`·`os.system`·`os.spawn*`·`_winapi.CreateProcess`를 감싸지만 `asyncio` 서브
  프로세스 생성 함수는 감싸지 않는다(현재 프로덕션 코드는 이를 쓰지 않는다). `_winapi.CreateProcess` 계층은 이
  Linux 환경에서 설치·실행되지 않아 대응 테스트가 스킵되며, Windows에서 별도 실행 검증이 필요하다.
